# VIP Tattoo — План курсу (плагін)

WordPress-плагін, що публікує інтерактивну 23-слайдову презентацію плану курсу як окрему, повністю незалежну сторінку (без хедера/футера/меню теми) — за тим самим принципом, що й основний плагін лендингу `vip-tattoo-landing`.

Сайт нічого не збирає і не зберігає про відвідувачів. На сторінці рівно дві кнопки:
1. «Открыть доступ к обучению» — веде напряму на Stripe Payment Link (або PayPal), оплату повністю приймає провайдер; він же сам робить редирект після оплати (напряму в Telegram — налаштовується в кабінеті Stripe/PayPal, а не в цьому плагіні).
2. «Написать Виктории» — веде напряму в особистий Telegram Вікторії.

Плагін лише фіксує клік по кнопках (без email/телефону — просто подія кліку) і, окремо, слухає вебхуки Stripe/PayPal, щоб миттєво (без збереження) переслати підтверджену оплату в Meta Conversions API.

## Встановлення

1. Заархівуй папку `vip-tattoo-plan-viewer/` у `.zip`.
2. WordPress admin → «Плагіни» → «Додати новий» → «Завантажити плагін» → обери zip → «Встановити» → «Активувати».
3. Створи нову сторінку («Сторінки» → «Додати нову»), у боковій панелі «Атрибути сторінки» → «Шаблон» обери **«VIP Tattoo — План курсу (презентація)»**, опублікуй.

## Налаштування

В адмінці зліва з'являться два пункти меню:

**«VIP Tattoo План»**:
- **Оплата і кнопки** — посилання на Stripe Payment Link (кнопка «Открыть доступ к обучению»), текст обох кнопок, посилання другої кнопки (особистий Telegram).
- **SEO** — title, description, Open Graph, canonical, robots, JSON-LD Course schema.
- **Піксели / аналітика** — GA4, Google Tag Manager, Meta (Facebook) Pixel, TikTok Pixel. Кожен вмикається лише якщо заповнене відповідне поле. Клік по кнопці «Открыть доступ к обучению» шле подію Lead одразу в усі підключені пікселі (GA4: `generate_lead`, Meta: `Lead`, TikTok: `Lead`).
- **Вебхук** — на кожну подію (перегляд/клік оплати/клік «Написати») шле підписаний (HMAC-SHA256) POST-запит на вказаний URL (Zapier / Make / власна CRM).
- **Telegram-сповіщення** — надсилає повідомлення адміну в Telegram при кожному кліку на кнопку оплати.

**«VIP Tattoo План: Оплата»** — Stripe/PayPal test і live ключі, потрібні виключно для перевірки вебхуків (нижче):
- **Stripe** — режим Test/Live + окремий Webhook Signing Secret для кожного (обидва завжди залишаються збереженими, перемикач лише каже, який з них зараз активний).
- **PayPal** — режим Sandbox/Live + Client ID/Secret/Webhook ID для кожного (потрібні PayPal-у для власного виклику verify-webhook-signature).
- Адреси вебхуків показані прямо на сторінці — просто скопіювати в кабінет Stripe/PayPal.
- **Жодних ключів для прийому оплати тут немає** — сама оплата йде повністю на стороні Stripe/PayPal через посилання/кнопку з «Оплата і кнопки» вище; ці вебхуки лише повідомляють плагін, що оплата відбулась, аби переслати це в Meta (нижче).

**«VIP Tattoo План: Оплата → Meta Conversions API»** (підменю) — серверна відправка події `Purchase` напряму в Meta, оскільки після оплати покупець одразу редиректиться в Telegram, а не назад на сайт, тому клієнтський піксель цю подію не бачить:
- **Pixel ID**, **Access Token** (з Events Manager → піксель → Conversions API), **Test Event Code** (опційно, для перевірки в «Тестирование событий»).
- Спрацьовує автоматично на хук `vip_tattoo_plan_purchase_confirmed`, коли Stripe/PayPal підтверджують оплату вебхуком — для БУДЬ-ЯКОЇ завершеної оплати на акаунті, включно з тими, що йдуть через звичайне посилання/кнопку на сторінці (жодного власного чекауту плагін не створює).
- Email/телефон (якщо провайдер їх передав у вебхуку) хешуються (SHA-256) і одразу забуваються — ніде в базі даних не зберігаються.
- Внизу — таблиця останніх спроб відправки (ідентифікатор події Stripe/PayPal, статус, сира відповідь Meta з `fbtrace_id`, час) — без жодних персональних даних у логах.

## Архітектура (коротко)

- `vip-tattoo-plan-viewer.php` — реєстрація шаблону сторінки, SEO/пікселі head-виводу, підстановка плейсхолдерів у `content/body-plan.html`.
- `includes/settings.php` — адмін-сторінка основних налаштувань (nonce + санітизація всіх полів).
- `includes/tracking.php` — таблиця подій, REST-роут `/vip-tattoo-plan/v1/track`, ідемпотентний інсерт (UNIQUE KEY на visit_token+event_type), вихідний вебхук, Telegram-нотифікація адміну.
- `includes/payments.php` — окрема адмін-сторінка «Оплата» (test/live ключі Stripe та PayPal, лише для вебхуків), REST-роути `/stripe-webhook` і `/paypal-webhook`, крихітна таблиця-ідемпотентність (тільки `provider` + `event_id`, без жодних персональних даних) щоб не відправити один Purchase у Meta двічі при повторній доставці вебхука, хук `vip_tattoo_plan_purchase_confirmed` для сторонніх інтеграцій.
- `includes/meta-capi.php` — Meta Conversions API: надсилає `Purchase` на хук `vip_tattoo_plan_purchase_confirmed`, власна таблиця логів спроб відправки (без PII), підменю налаштувань під «VIP Tattoo План: Оплата».
- `templates/vip-tattoo-plan-viewer.php` — сама сторінка (повністю самодостатня, без залежності від теми).
- `content/body-plan.html` — розмітка усіх 23 слайдів з плейсхолдерами (`{{ASSET_URL}}`, `{{STRIPE_CHECKOUT_URL}}`, `{{CTA_PRIMARY_TEXT}}`, `{{CTA_SECONDARY_TEXT}}`, `{{CONTACT_URL}}`) — рівно дві кнопки, ніякої форми.
- `css/plan-viewer.css` — стилі презентації (ідентичні `docs/index.html`).
- `js/track.js` — клієнтський трекер (view/checkout_click/contact_click — лише факт кліку, без жодних даних користувача — + піксель-виклики).
- `assets/slides/`, `assets/icons/` — зображення слайдів та іконок, вбудовані в плагін (не залежить від папки `docs/`).

Ця гілка (`wp-plugin-development`) розробляється незалежно від гілки `pdf-plan-development` — зміни тут не зачіпають сам PDF-файл в іншій гілці.
